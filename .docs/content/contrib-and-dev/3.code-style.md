# Code Style

Formatting and naming conventions are defined in [`.editorconfig`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/blob/main/.editorconfig) at the repo root and are **enforced in CI** (see [CI/CD](./2.ci-cd.md)) via a JetBrains ReSharper cleanup pass — not just advisory.

## Applying formatting locally

```bash
dotnet tool install -g JetBrains.ReSharper.GlobalTools
dotnet restore ArmoniK.Extensions.CSharp.sln
jb cleanupcode --profile="Full Cleanup With Headers" ArmoniK.Extensions.CSharp.sln
```

Run this before opening a pull request — the `code-formatting.yml` workflow runs the exact same command and fails the PR if it produces any diff.

## Notable conventions

- 2-space indentation, LF line endings, UTF-8, final newline — applied to `.cs`, `.csproj`, `.json`, `.xml`, `.props`, `.targets`, and more.
- Naming: private instance/static fields use `lowerCamelCase_` (trailing underscore); private static readonly fields and private constants use `UpperCamelCase`.
- Preferred modifier order: `public, private, protected, internal, new, static, abstract, virtual, sealed, readonly, override, extern, unsafe, volatile, async`.
- `var` is suggested wherever the type is apparent, for built-in types, and elsewhere.
- `using` directive groups are kept separate (e.g. BCL `using System;` imports separated by a blank line from `ArmoniK.*` imports), matching the pattern visible throughout the codebase.
- Public members should carry XML doc comments — CI treats missing/malformed doc comments (`CS1570`–`CS1591`) as build errors.

## Commit and PR conventions

- PR titles must follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) (enforced by `semantic-pull-request.yml`).
- Use the [PR template](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/blob/main/.github/PULL_REQUEST_TEMPLATE.md) when opening a pull request.
