# Error Handling

## `ArmoniKSdkException`

`ArmoniK.Extensions.CSharp.Common.Exceptions.ArmoniKSdkException` (mirrored in the client and worker assemblies) is the exception type this SDK raises for its own validation and wrapping errors — for example, `TaskDefinition.WithOutput(...)` throws it if you pass an output `BlobDefinition` that already has a `BlobHandle` set, and `TaskOptionExt.GetDynamicLibrary()` throws it if the expected `LibraryPath`/`Symbol`/`LibraryBlobId` options are missing.

```csharp
try
{
  var task = new TaskDefinition().WithOutput("result", someAlreadyResolvedBlob);
}
catch (ArmoniKSdkException ex)
{
  logger.LogError(ex, "Invalid task definition");
}
```

## gRPC status codes

Calls to the ArmoniK control plane surface failures as standard [gRPC status codes](https://grpc.github.io/grpc/core/md_doc_statuscodes.html), typically wrapped in an `RpcException`. The most common ones you'll see:

| gRPC status | Typical cause |
|---|---|
| `OK` | Request completed successfully |
| `CANCELLED` | The session or task was explicitly cancelled |
| `INVALID_ARGUMENT` | Malformed request — e.g. missing required field, invalid partition ID |
| `NOT_FOUND` | The referenced session, task, or blob does not exist or was deleted |
| `ALREADY_EXISTS` | Attempted to create a resource with an ID that already exists |
| `PERMISSION_DENIED` | Authenticated, but lacking the required role |
| `UNAUTHENTICATED` | No valid client certificate/credentials presented (mTLS enabled) |
| `RESOURCE_EXHAUSTED` | Task queue full or cluster resource limits reached |
| `FAILED_PRECONDITION` | Operation not allowed in the current state — e.g. submitting to a closed/cancelled session |
| `UNAVAILABLE` | Control plane unreachable or not yet ready (also transient during rolling restarts) |
| `INTERNAL` | Unexpected server-side error — check control plane logs |
| `DEADLINE_EXCEEDED` | Request timed out |

### Common scenarios

**`FAILED_PRECONDITION`: session is not in a running state**
Tasks cannot be submitted to a session that is closed, cancelled, or paused. Check session status via `client.SessionService`/`sessionHandle` before submitting.

**`UNAVAILABLE`**
The control plane isn't ready — retry with backoff (see the `RetryInitialBackoff`/`RetryBackoffMultiplier`/`RetryMaxBackoff` settings in [Configuration](../user-guide/4.configuration.md), which already apply this automatically at the channel level).

**`PERMISSION_DENIED` / `UNAUTHENTICATED`**
Check the mTLS client certificate configuration (`Grpc:ClientCert`/`Grpc:ClientKey`/`Grpc:ClientP12`) against the cluster's authentication setup — see the [main ArmoniK authentication guide](https://armonik.readthedocs.io/en/latest/content/user-guide/4.how-to-configure-authentication.html).
