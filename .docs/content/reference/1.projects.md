# Projects

The repository is a single solution, [`ArmoniK.Extensions.CSharp.sln`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/blob/main/ArmoniK.Extensions.CSharp.sln), made up of:

## Published NuGet packages

- **`ArmoniK.Extensions.CSharp.Client`** (`netstandard2.0`) — the library exposing the APIs an ArmoniK client application uses: `ArmoniKClient`, the services (`IBlobService`, `ITasksService`, ...), handles (`BlobHandle`, `SessionHandle`, `TaskHandle`), and the LINQ query API.
- **`ArmoniK.Extensions.CSharp.Common`** (`netstandard2.0`) — shared domain types used by both the client and the worker libraries (`BlobDefinition`, `TaskDefinition`, `TaskConfiguration`, `ArmoniKSdkException`, ...). No project references — this is the base library.
- **`ArmoniK.Extensions.CSharp.Worker`** (`net8.0`) — common logic shared by static and dynamic workers: `ArmoniKWorker.Run<T>()`, `StaticServiceRequestContext<T>`, `SdkTaskRunner`.
- **`ArmoniK.Extensions.CSharp.Worker.Interfaces`** (`net8.0`) — the minimal `IWorker` contract. A worker that only relies on dynamic loading needs no other dependency.

## Deployable applications

- **`ArmoniK.Extensions.CSharp.DynamicWorker`** — a web application implementing the dynamic-loading host described in [Static vs. Dynamic Workers](../user-guide/1.static-vs-dynamic-workers.md). Built and published as the `dockerhubaneo/armonik-dynamic-dotnet-worker` Docker image; must be deployed as a container in an ArmoniK partition.
- **`StaticWorkerExample`** — a runnable example implementing `IWorker` directly, built as its own container image; illustrates the static worker approach end-to-end.

## Examples

- **`DynamicWorkerExample`** — a class library only, implementing `IWorker`, meant to be zipped and uploaded for the dynamic-loading feature.
- **`UsageExample`** — a console application showing a full client-side flow: connect, open a session, upload a dynamic worker library, submit a task, wait for its result, download it.

## Tests

- **`Tests`** — unit tests (NUnit + Moq) exercising the client library against a mocked gRPC `CallInvoker`. See [Building and Testing](../contrib-and-dev/1.building-and-testing.md).
- **`End2EndTests/ArmoniK.EndToEndTests.Client`** — NUnit tests that submit real tasks against a deployed ArmoniK cluster (Gauss problem, priority, failing tasks, blob-creation ordering, task/partition queries at scale).
- **`End2EndTests/ArmoniK.EndToEndTests.Worker`** — the corresponding worker-side implementations, deployed via the dynamic-loading pathway on top of a pre-built `dockerhubaneo/armonik_csharp_worker_dll` image.

See [Building and Testing](../contrib-and-dev/1.building-and-testing.md) for how to build and run all of the above locally.
