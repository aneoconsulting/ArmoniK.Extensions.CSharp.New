# Querying with LINQ

`IBlobService`, `ITasksService`, and `IPartitionsService` each expose an `AsQueryable()` method, so you can filter, sort, and page through blobs, tasks, and partitions using regular LINQ syntax — the query is translated into ArmoniK's protobuf filter format and executed remotely.

```csharp
IQueryable<BlobState>     blobs      = client.BlobService.AsQueryable();
IQueryable<TaskSummary>   tasks      = client.TasksService.AsQueryable();
IQueryable<Partition>     partitions = client.PartitionsService.AsQueryable();
```

## Supported operations

- `.Where(predicate)` — supports `&&`, `||`, `==`, `!=`, and collection `.Contains(...)` over the entity's filterable members (e.g. for `BlobState`: `SessionId`, `BlobId`, `BlobName`, `CreatedBy`, `CreateAt`, `CompletedAt`, `Status`, `OwnerId`, `OpaqueId`, `Size`).
- `.OrderBy(keySelector)` / `.OrderByDescending(keySelector)` — the last one applied wins if chained.
- `.First()` / `.First(predicate)` / `.FirstOrDefault()` / `.FirstOrDefault(predicate)` — a trailing predicate is merged into any existing `.Where(...)` filter.
- `.WithPageSize(pageSize)` — controls the page size used when paginating through results server-side.
- `.AsAsyncEnumerable()` / `.ToAsyncEnumerable()` — stream results as an `IAsyncEnumerable<T>` instead of forcing a synchronous enumeration.

Not every member is filterable on every entity — e.g. attempting to filter `BlobState` by a `TaskStatus`-only field throws `InvalidOperationException` at query-build time, not at the server.

## Examples

Filter and sort:

```csharp
var query = client.BlobService.AsQueryable()
                  .Where(blobState => blobState.SessionId == "session1")
                  .OrderBy(blobState => blobState.BlobId);

List<BlobState> results = await query.AsAsyncEnumerable().ToListAsync();
```

Filter, then grab the first match with an extra predicate:

```csharp
var query = client.BlobService.AsQueryable()
                  .Where(blobState => blobState.SessionId == "session1");

var completed = query.FirstOrDefault(blobState => blobState.Status == BlobStatus.Completed);
```

Stream large result sets page by page:

```csharp
var query = client.TasksService.AsQueryable()
                  .Where(task => task.SessionId == session.SessionInfo.SessionId)
                  .WithPageSize(50);

await foreach (var task in query.ToAsyncEnumerable())
{
  Console.WriteLine(task.TaskId);
}
```

Convert a `TaskSummary` query into full `TaskState` details:

```csharp
IAsyncEnumerable<TaskState> details = client.TasksService.AsQueryable()
                                            .Where(task => task.Status == TaskStatus.Completed)
                                            .AsTaskDetailed();
```

This is the same mechanism the SDK uses internally to implement [callback polling](./2.submitting-tasks.md#2-callbacks-via-icallback): the `SessionHandle`'s background poller batches blob-id lookups with a query like

```csharp
client.BlobService.AsQueryable()
      .Where(blobState => idsChunk.Contains(blobState.BlobId) && blobState.Status != BlobStatus.Created)
      .WithPageSize(pageSize);
```
