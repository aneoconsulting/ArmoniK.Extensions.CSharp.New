# Hello World — Dynamic Worker

A **dynamic worker** lets a single deployed worker image run many different task implementations, loaded on demand. Your `IWorker` implementation is a plain class library; it gets zipped, uploaded as a blob, and loaded at runtime by the generic `ArmoniK.Extensions.CSharp.DynamicWorker` host process inside an isolated `AssemblyLoadContext`. See [Static vs. Dynamic Workers](../user-guide/1.static-vs-dynamic-workers.md) for the trade-offs.

This guide follows the [`DynamicWorkerExample`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/tree/main/DynamicWorkerExample) and [`UsageExample`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/tree/main/UsageExample) projects.

## Step 1: Implement `IWorker` as a class library

Only reference `ArmoniK.Extensions.CSharp.Worker.Interfaces` — no `Program.cs`, no gRPC hosting. The implementation is identical to the static worker's:

```csharp
public class HelloWorker : IWorker
{
  public async Task<TaskResult> ExecuteAsync(ISdkTaskHandler taskHandler,
                                              ILogger            logger,
                                              CancellationToken   cancellationToken)
  {
    var name = taskHandler.Inputs["name"].GetStringData();

    await taskHandler.Outputs["helloResult"]
                      .SendStringResultAsync($"Hello {name} from dynamic worker!",
                                              cancellationToken: cancellationToken);

    return TaskResult.Success;
  }

  public Task<HealthCheckResult> CheckHealth(CancellationToken cancellationToken = default)
    => Task.FromResult(HealthCheckResult.Healthy());
}
```

## Step 2: Publish and zip the library

The project sets `OutputType=Library` and adds two MSBuild targets that run automatically after `dotnet publish`:

```xml
<Target Name="CreateDirectories" AfterTargets="Publish">
  <MakeDir Directories="./packages/" />
</Target>
<Target Name="ZipOutputPath" AfterTargets="CreateDirectories">
  <ZipDirectory SourceDirectory="./publish/" DestinationFile="./packages/$(MSBuildProjectName)-v$(Version).zip" Overwrite="true" />
</Target>
```

```bash
dotnet publish --self-contained -c Release -r linux-x64 -f net8.0 .
# -> ./packages/DynamicWorkerExample-v1.0.0.0.zip
```

## Step 3: Deploy the generic dynamic worker host

Unlike the static case, you don't build your own worker image — you deploy the pre-built [`dockerhubaneo/armonik-dynamic-dotnet-worker`](https://hub.docker.com/r/dockerhubaneo/armonik-dynamic-dotnet-worker) image (built from [`ArmoniK.Extensions.CSharp.DynamicWorker`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/tree/main/ArmoniK.Extensions.CSharp.DynamicWorker)) to an ArmoniK partition. It exposes two configuration keys (`ServiceAssemblyPath`, `ZipPath`) that default to scratch directories inside the container — no per-worker customization needed.

## Step 4: Submit a task and upload the library

```csharp
// 1. Configure and create the client
var taskOptions = new TaskConfiguration(maxRetries: 2,
                                        priority: 1,
                                        partitionId: "dllworker",
                                        maxDuration: TimeSpan.FromHours(1));

var properties = new Properties(configuration);
var client      = new ArmoniKClient(properties, loggerFactory);

// 2. Describe the library to load: fully-qualified type name + path inside the zip
var dynamicLib = new DynamicLibrary
{
  Symbol      = "DynamicWorkerExample.HelloWorker",
  LibraryPath = "DynamicWorkerExample/1.0.0.0/DynamicWorkerExample.dll",
};

// 3. Open a session and upload the zipped library as a blob
await using var session = await client.CreateSessionAsync(["dllworker"], taskOptions, closeOnDispose: false);

await client.BlobService.SendDllBlobAsync(session, dynamicLib, "./packages/DynamicWorkerExample-v1.0.0.0.zip",
                                          manualDeletion: false, CancellationToken.None);
// this stamps dynamicLib.LibraryBlobId

// 4. Describe the task — WithLibrary() ties it to the uploaded library
var task = new TaskDefinition().WithLibrary(dynamicLib)
                                .WithInput("name", InputBlobDefinition.FromString("name", "world"))
                                .WithOutput("helloResult", OutputBlobDefinition.CreateOutput("Result"))
                                .WithTaskOptions(taskOptions);

// 5. Submit and wait for completion
var taskHandle = session.Submit(task);
var taskInfos  = await taskHandle.GetTaskInfosAsync();
var resultBlob = taskInfos.Outputs["helloResult"];

await client.EventsService.WaitForBlobsAsync(session, [resultBlob]);

var resultBytes = await client.BlobService.DownloadBlobAsync(resultBlob);
Console.WriteLine(Encoding.UTF8.GetString(resultBytes)); // "Hello world from dynamic worker!"
```

The dynamic worker host caches loaded libraries per session, keyed by `Symbol` + `LibraryBlobId` — submitting more tasks with the same `dynamicLib` in the same session reuses the already-loaded assembly instead of re-uploading or re-extracting it.

## Trying it locally

`DynamicWorkerExample/DeployWorkerInWsl.ps1` (Windows/WSL) and `End2EndTests/ArmoniK.EndToEndTests.Worker/DeployWorker.sh` (Linux) automate: publishing the worker, discovering your local ArmoniK cluster's ingress address, and rewriting the client's `appsettings.json` `Grpc:EndPoint` to point at it.
