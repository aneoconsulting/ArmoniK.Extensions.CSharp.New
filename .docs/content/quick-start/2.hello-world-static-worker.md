# Hello World — Static Worker

A **static worker** is a self-contained application: your `IWorker` implementation is compiled directly into the worker's Docker image, and that image only ever runs that one implementation. It's the simplest way to get started. See [Static vs. Dynamic Workers](../user-guide/1.static-vs-dynamic-workers.md) for when to prefer this over the [dynamic loading approach](./3.hello-world-dynamic-worker.md).

The full working sample this guide is based on lives in [`StaticWorkerExample`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/tree/main/StaticWorkerExample).

## Step 1: Implement `IWorker`

Add a reference to `ArmoniK.Extensions.CSharp.Worker.Interfaces` (transitively available if you already reference `ArmoniK.Extensions.CSharp.Worker`) and implement the two-method contract:

```csharp
internal class HelloWorker : IWorker
{
  public async Task<TaskResult> ExecuteAsync(ISdkTaskHandler taskHandler,
                                              ILogger            logger,
                                              CancellationToken   cancellationToken)
  {
    var name = taskHandler.Inputs["name"].GetStringData();

    await taskHandler.Outputs["helloResult"]
                      .SendStringResultAsync($"Hello {name} from static worker!",
                                              cancellationToken: cancellationToken);

    return TaskResult.Success;
  }

  public Task<HealthCheckResult> CheckHealth(CancellationToken cancellationToken = default)
    => Task.FromResult(HealthCheckResult.Healthy());
}
```

Inputs and outputs are looked up by the same names the client used when building the `TaskDefinition` (`"name"` and `"helloResult"` here) — see [step 4](#step-4-submit-a-task-from-the-client). `taskHandler.Inputs` is an `IReadOnlyDictionary<string, TaskInput>` and `taskHandler.Outputs` an `IReadOnlyDictionary<string, TaskOutput>` — read-only and write-only views over the underlying blob, respectively.

A new `HelloWorker` instance is created for every task, so it must have a public parameterless constructor.

## Step 2: Host the worker

```csharp
internal static class Program
{
  private static void Main(string[] args)
    => ArmoniKWorker.Run<StaticServiceRequestContext<HelloWorker>>();
}
```

`ArmoniKWorker.Run<T>()` (from `ArmoniK.Extensions.CSharp.Worker`) starts the gRPC worker server that ArmoniK's compute plane dispatches tasks to. `StaticServiceRequestContext<HelloWorker>` instantiates a fresh `HelloWorker` for each incoming task.

## Step 3: Containerize and deploy

Build a Docker image from a `.NET 8` base (see [`StaticWorkerExample/Dockerfile`](https://github.com/aneoconsulting/ArmoniK.Extensions.CSharp.New/blob/main/StaticWorkerExample/Dockerfile) for the full multi-stage build) and push it to a registry your ArmoniK cluster can pull from. Configure an ArmoniK partition to use that image — see the [deployment configuration guide](https://armonik.readthedocs.io/en/latest/content/user-guide/7.deployment-configuration.html) in the main ArmoniK docs.

## Step 4: Submit a task from the client

On the client side, add a reference to `ArmoniK.Extensions.CSharp.Client` and:

```csharp
// 1. Configure and create the client
var taskOptions = new TaskConfiguration(maxRetries: 2,
                                        priority: 1,
                                        partitionId: "static-hello", // the partition your worker is deployed to
                                        maxDuration: TimeSpan.FromMinutes(5));

var properties = new Properties(configuration); // reads the "Grpc" section, see appsettings.json below
var client      = new ArmoniKClient(properties, loggerFactory);

// 2. Open a session
await using var session = await client.CreateSessionAsync(["static-hello"], taskOptions, closeOnDispose: true);

// 3. Describe the task: inputs, outputs, options — no WithLibrary() needed for a static worker
var task = new TaskDefinition().WithInput("name", InputBlobDefinition.FromString("name", "world"))
                                .WithOutput("helloResult", OutputBlobDefinition.CreateOutput("Result"))
                                .WithTaskOptions(taskOptions);

// 4. Submit and wait for completion
var taskHandle    = session.Submit(task);
var taskInfos     = await taskHandle.GetTaskInfosAsync();
var resultBlob    = taskInfos.Outputs["helloResult"];

await client.EventsService.WaitForBlobsAsync(session, [resultBlob]);

var resultBytes = await client.BlobService.DownloadBlobAsync(resultBlob);
Console.WriteLine(Encoding.UTF8.GetString(resultBytes)); // "Hello world from static worker!"
```

`Properties` reads its `Grpc` section (`EndPoint`, TLS settings, retry backoff) from your app's configuration — point `Grpc:EndPoint` at your cluster's control-plane URL:

```json
{
  "Grpc": {
    "EndPoint": "http://<control-plane-host>:5001"
  }
}
```

Congratulations — you've run your first task on a static ArmoniK worker! For a deeper look at submission batching, callbacks, and the LINQ query API, continue to the [User Guide](../user-guide/1.static-vs-dynamic-workers.md).
