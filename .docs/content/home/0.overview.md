## What is ArmoniK.Extensions.CSharp ?

`ArmoniK.Extensions.CSharp` is a C# SDK for [ArmoniK](https://github.com/aneoconsulting/ArmoniK) that lets you describe a task graph directly in C#, with explicit data dependencies between tasks, and embraces `async`/`await` throughout. It:

- Introduces **blobs** as a single, consistent abstraction for all data flowing in and out of tasks (payloads, results, and data dependencies).
- Introduces **task nodes** (`TaskDefinition`) to describe a task's inputs, outputs, and options in one place, making it easier to build dependency graphs.
- Splits responsibilities across focused **services** (`SessionService`, `BlobService`, `TasksService`, `EventsService`, ...) instead of one large client class.
- Is fully asynchronous, and batches task submissions and result callbacks in the background for better throughput.
- Adds LINQ-style filtering (`IQueryable`) over blobs, tasks, and partitions.

## Two ways to run compute code

ArmoniK executes your code inside a **worker**. This SDK supports two ways of building one:

- **Static workers** — you implement `IWorker` in a project, build a Docker image, and deploy it to an ArmoniK partition. The worker only ever runs the code that was baked into that image.
- **Dynamic workers** — you implement `IWorker` in a plain class library, zip the published output, and upload it as a blob at submission time. The generic `ArmoniK.Extensions.CSharp.DynamicWorker` host image downloads, extracts, and loads your library at runtime (in an isolated, collectible `AssemblyLoadContext`), so a single deployed worker image can run many different task implementations.

See the "Static vs. Dynamic Workers" page under User Guide for a detailed comparison.
